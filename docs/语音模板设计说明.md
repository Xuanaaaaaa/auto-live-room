# 语音模板设计说明

## 目标

语音模板用于在直播查岗链路里，根据已检索到的岗位字段快速生成一段稳定可播的中文口播。它的第一目标不是写得最华丽，而是让画面、字幕和声音保持同步。

实时口播目标：

- 时长控制在 10 到 15 秒左右。
- 文案长度优先控制在 70 到 110 个中文字符。
- 只播岗位页面已经展示的信息，不编造薪资、学历、经验、福利或风险。
- 字段缺失时尽量跳过，不把缺字段播成报错感。
- 对外仍输出 `NarrationResult`，保持 `events/traces/OBS` 消费格式不变。

## 设计原则

模板不做一条死句子，而是做“事实片段拼装器”：

```text
JobPayload
  -> 提取事实片段
  -> 按优先级选择片段
  -> 控制字符预算
  -> build_narration_result(source="template")
```

必选片段是岗位核心信息：

```text
现在看到的是{city}的{job_name}，公司是{company_name}。
```

候选片段按信息价值排序：

1. 推荐理由：`recommendedMessage`
2. 技能或方向关键词：`tags` / `skill_tags`
3. 学历、经验、岗位类型：`degree` / `education` / `experience` / `job_type`
4. 薪资：`salary` / `salary_desc` / `salary_range`
5. 企业信息：`company_title_key` / `company_type_key`
6. 收口提醒：方向匹配时看详情，具体要求以页面为准

## 缺字段策略

实时口播里不主动播大量“页面暂未展示”。例如薪资缺失、经验缺失、学历缺失通常不播。

只有当可用字段很少时，才用保守收口：

```text
页面信息有限，建议重点核对岗位职责和投递入口。
```

风险提示仍由代码写入 `risk_tips`，用于 trace/debug，不默认进入口播。

## 模板示例

通用岗位：

```text
现在看到的是杭州的 Python 后端开发岗位，公司是某某科技。页面关键词包括 Python、数据库、接口开发，要求本科以上，有后端经验。方向匹配的话，可以重点看一下详情。
```

实习或校招：

```text
这条是腾讯音乐娱乐集团在深圳开放的 QQ 音乐公关传播实习生，岗位类型是实习。适合正在看校招或实习的同学重点留意。
```

信息较少：

```text
现在打开的是北京丰台的后端开发工程师，公司是谊安。页面信息有限，建议重点核对岗位职责和投递入口。
```

## 与 LLM 的关系

模板和 LLM 都只负责生成 `spoken_text`。`title/tags/risk_tips/source` 统一由代码补齐：

```text
LLM spoken_text
  -> build_narration_result()

Template spoken_text
  -> build_narration_result()
```

这样后续可以在不影响 orchestrator、monitor、stats、OBS audio 的前提下切换策略：

- 实时链路优先模板，保证低延迟。
- 本地 LLM 或云端 LLM 做精修，命中缓存后复用。
- LLM 超时时回退模板。

## 对外兼容性

模板实现只改变语音模块内部的文案生成方式，不改变对外 JSONL 结构：

- `narration.spoken_text` 仍然存在。
- `narration.title/tags/risk_tips/source` 仍然存在。
- `completed.audio_path` 仍然存在。
- OBS 音频脚本仍只消费 `audio_path`。
- OBS 文字脚本默认仍消费弹幕 `raw_text`。
